# Five-Phase Dashboard Quality Build

The dashboard now shares one versioned decision contract across Command Center, Lineup, My Roster, Acquisition Targets, Trade Analyzer, Validation, and Draft.

## Phase 1: trusted data

Every source exposes freshness, usability, confidence, and required/optional status. Expired required sources degrade the system instead of silently masquerading as current data.

## Phase 2: league outcomes

Lineup assignment uses legal roster slots, projected points when available, market value only as a labeled fallback, and close-decision comparisons. Roster assessment is league-format-aware and identifies structural depth gaps.

## Phase 3: transactions

Acquisition results combine projections, roster fit, market value, bounded momentum, a matching drop, and a budget-relative FAAB range. Trade results separate fairness from the active roster's projected and positional benefit.

## Phase 4: decision-first experience

Command Center ranks a small set of actionable, reversible decisions. All tabs expose the same source-health strip, confidence vocabulary, keyboard-operable tab navigation, and progressive evidence.

## Phase 5: proof and release safety

Pure decision contracts have deterministic scenario tests. Static product contracts cover every tab, stale-data labeling, accessibility semantics, performance budgets, and production release policy. Existing draft, auction, provider, browser, and historical backtest suites remain authoritative for their domains.

No descriptive signal may gain predictive influence without held-out improvement. No stale or incomplete source may be presented as current.
