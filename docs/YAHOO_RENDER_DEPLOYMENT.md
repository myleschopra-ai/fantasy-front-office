# Yahoo Adapter Deployment on Render

## What this deploys

- Flask Yahoo OAuth and roster-sync adapter
- Gunicorn production server
- Redis-backed server-side sessions
- HTTPS through Render
- Health check at `/health`

OAuth tokens remain in Redis and are not exposed to GitHub Pages or browser storage.

## 1. Create a Yahoo Developer application

Create a server-side web application in Yahoo Developer Network with Fantasy Sports read access.

Use this callback URL after the Render service name is known:

```text
https://<render-service>.onrender.com/yahoo/callback
```

Retain the Yahoo consumer key and consumer secret. Never commit them.

## 2. Create the Render blueprint

In Render:

1. Choose **New > Blueprint**.
2. Connect `myleschopra-ai/fantasy-front-office`.
3. Select branch `main`.
4. Render reads `render.yaml` and proposes:
   - `fantasy-front-office-yahoo` web service
   - `fantasy-front-office-yahoo-redis` Redis service
5. Enter secret values when prompted.

## 3. Required environment variables

```text
YAHOO_CLIENT_ID=<Yahoo consumer key>
YAHOO_CLIENT_SECRET=<Yahoo consumer secret>
YAHOO_SESSION_SECRET=<generated by Render>
YAHOO_REDIRECT_URI=https://<render-service>.onrender.com/yahoo/callback
DASHBOARD_ORIGIN=https://myleschopra-ai.github.io
REDIS_URL=<provided by Render blueprint>
```

`YAHOO_REDIRECT_URI` must exactly match the callback registered with Yahoo.

## 4. Verify deployment

Open:

```text
https://<render-service>.onrender.com/health
```

Expected response:

```json
{"status":"ok","service":"yahoo-fantasy-oauth"}
```

## 5. Connect the dashboard

1. Open `yahoo-connect.html` from the dashboard.
2. Save the Render service root URL, without a trailing path.
3. Select the Yahoo league in the global league switcher.
4. Enter the Yahoo league key, preferably the complete key such as `449.l.123456`.
5. Choose **Connect Yahoo** and approve access.
6. Return to the dashboard and choose **Sync Yahoo**.
7. Select the correct team when prompted.

The backend URL, league key, selected league, selected team, and latest normalized roster snapshot persist in browser local storage until explicitly removed.

## Security notes

- Do not place Yahoo secrets in GitHub Pages JavaScript, repository files, or screenshots.
- Redis is mandatory for production because the default Flask session stores session data client-side.
- Cookies are Secure, HttpOnly, and SameSite=None to support the GitHub Pages-to-Render cross-site OAuth flow.
- Disconnecting clears the server-side Yahoo session; removing a league ID clears only the browser's saved identifier and cached snapshot.
